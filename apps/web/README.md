# @vjt/web

The web app: a Vite + React single-page app with React Router, Tailwind CSS 4 and shadcn/ui. It shares logic with the phone app through `@vjt/core`, `@vjt/api-client` and `@vjt/design` (ADR-0010). Its screens follow [docs/design/ui-plan.md](../../docs/design/ui-plan.md).

## Develop

From the repo root:

```sh
pnpm turbo run dev --filter=@vjt/web
```

Turbo builds the shared packages this app imports (`@vjt/core`, `@vjt/api-client`, `@vjt/design`) first, then starts `vite` on http://localhost:5173. The task is defined in `apps/web/turbo.json` and is not cached. Only the web package has a `dev` task in turbo, so a bare `turbo run dev` would also start the other packages' dev scripts. Always pass the filter.

`vite` proxies the API paths (`/auth`, `/me`, `/stories`, ...) to the Go server, so login is same-origin as in production. The proxy target defaults to `http://localhost:8080`. Point it elsewhere with `VJT_API_ORIGIN` (turbo passes it through to the task):

```sh
VJT_API_ORIGIN=http://docker-dev.internal:8080 pnpm turbo run dev --filter=@vjt/web
```

A page load (a request with `Accept: text/html`) is never proxied, so reloading `/stories/12` gets the app, as it does from the Go server. The list of proxied prefixes is in `api-prefixes.ts`; `src/vite-proxy.test.ts` fails if it misses a top-level path in `api/openapi.yaml`.

## Check

```sh
pnpm --filter @vjt/web typecheck
pnpm --filter @vjt/web lint
pnpm --filter @vjt/web test
pnpm --filter @vjt/web build    # tsc --noEmit && vite build, output in dist/
```

## Conventions

- Colours, type sizes and fonts come from `@vjt/design` (through the Tailwind classes or `var(--…)`). The lint rules `vjt/no-hardcoded-color` and `vjt/no-inline-font-size` reject hex and rgb literals (also inside template strings) and numeric font sizes.
- Theme (Light / Dark / System) and the Story text size are saved per device in localStorage. The no-flash script in `src/theme/bootstrap.ts` is written into `index.html` by `vite.config.ts` and applies the theme before the first paint.
- **CSP:** that inline script is a `<script>` with no `src`. The server does not send a Content-Security-Policy today. If it ever adds `script-src 'self'`, the script will be blocked and the page will flash the wrong theme. The fix is to allow it with a hash of the script text (`sha256-…`, computed from the built `index.html`) or a per-response nonce that the build injects. Either way, keep the hash in step with `themeBootstrapScript()`.
- Fonts: `public/fonts/` holds the unicode-range slices generated by `scripts/subset-fonts.mjs`. `src/index.css` declares them.
- Focus: the ring utilities draw focus on components. Bare links and other interactive elements without a ring class get an outline from `src/index.css`.
- Route guard and `next` handling: `src/routes/RequireSession.tsx` and `src/routes/nextPath.ts`. Only same-origin paths are accepted after login.
